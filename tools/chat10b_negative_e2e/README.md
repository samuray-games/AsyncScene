# Чат 10Б V123 - изолированный negative E2E contract runner

**Статус: только STUB-контракт. НЕ реальный server/Worker/D1/E2E PASS.**

Содержит 10 исполняемых отрицательных сценариев NEG01-NEG10 из отдельного task-owned scope. Используется Node.js >=20, только стандартная библиотека. Нет браузера, HTTP listener, сетевых запросов, SQL, внешних библиотек, миграций или действий с аккаунтами. Все IDs вымышлены.

## Запуск в изолированном каталоге

```sh
node tools/chat10b_negative_e2e/run.mjs
node tools/chat10b_negative_e2e/run.mjs --json
```

Обе команды локально запускают 10 отрицательных сценариев и одну проверку маркировки provenance. JSON всегда содержит `endToEndRuntimePass:false` и `provenance:STUB_ONLY`, включая случай, когда все тесты прошли. Это предохранитель против подмены исполнения модели сервера настоящим испытанием.

## Границы импорта

- `adapter.mjs` - единственная точка смены test adapter, только в своей папке. По умолчанию явно использует `STUB`.
- `stub-authority.mjs` - чистая синхронная in-memory модель. Её rollback через `structuredClone`, глобальная уникальность и внешний `witness` лишь **моделируют** предполагаемые гарантии. Они НЕ проверяют SQL/D1 или конкурентные Cloudflare Workers.
- `provenance.mjs` - по каждому тесту закреплена маркировка `STUB`, владельцы потенциального настоящего модуля и точные GitHub SHA оригинальных *reference-only* исходников. Список `importedSourceModules` пуст. Ссылки на PR не являются импортом.
- `test/negative.test.mjs` - 10 проверок сценариев NEG01-NEG10 и один guard, который не даст тихо переименовать `STUB` в `SOURCE`.
- `run.mjs` - ограниченный 20 сек запуск Node child process, счётчик тестов и машиночитаемый отчёт без сетевых действий.
- `evidence/` - отчёты независимого локального запуска и манифест хешей.

## Переход на настоящие модули

Только новый отдельный разрешённый task-scoped change внутри `tools/chat10b_negative_e2e/`: меняется только собственный `adapter.mjs` на проверенный adapter, вызывающий оригинальный source module по проверенному точному Git SHA/публичному экспорту. Каждый scenario должен привязать реальный импорт, собственный version/fingerprint и negative expected output. До этого менять `implementation` в `SOURCE` запрещено. Подключение Worker/D1 или новых SQL/privileged routes потребует нового exact-scope OWNER TEST GO и отдельного исполнительного окружения; реальная транзакционная семантика не доказывается этим модельным циклом.

## Критические незакрытые условия

`critical_reviewer` по точному источнику+тестам, подлинный private original-byte Cloud Checkpoint с облачным SHA readback, локальная проверка политик и ownership. Недоступные независимые роли нельзя заменять собственным review; отсутствие checkpoint нельзя заменять текстом в Notion. Не писать в чужие каталоги, shared gameplay Worker, Web/docs, миграции, main или чужие PR.
